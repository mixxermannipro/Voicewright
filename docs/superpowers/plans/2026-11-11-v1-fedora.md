# Voicewright V1 Fedora Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Voicewright 1.0.0 für Fedora 45 KDE Wayland mit automatischem Einfügen, der freigegebenen Hintergrund-UI und geprüften RPM-/AppImage-Paketen liefern.

**Architecture:** Den getesteten Diktatkern behalten. Ein eigenes Wayland-Ausgabemodul besitzt die ausdrücklich freigegebene Portal-Sitzung; die App integriert es neben der bestehenden X11-/Windows-Ausgabe. Oberfläche und Paketierung folgen in getrennten überprüfbaren Schritten, nachdem der echte Wayland-Nachweis gelungen ist.

**Tech Stack:** Tauri 2, Rust 1.99.1, React 19, TypeScript, Node 24, Vitest, vorhandenes ashpd 0.14, XDG Desktop Portals, Tauri-Paketbau, Python-Paketprüfer, Podman für isolierte Tests.

**Spec:** `docs/superpowers/specs/2026-11-11-v1-fedora-design.md` (freigegeben).

**Execution:** Vom Anwender bestätigt: „Ja bitte umsetzen. Stelle keine fragen mehr. Entscheide selbst.“ Haupt-Agent arbeitet inline auf dem bereits angelegten Feature-Branch; keine neuen Umfangsfreigaben zwischen Tasks.

## Global Constraints

- Ziel: `1.0.0`, Fedora 45, Linux x64, KDE Plasma Wayland; keine unbelegte GNOME-/Windows-/macOS-Freigabe.
- Wayland-Einfügen ins **aktuell aktive Feld** ist Pflicht. Keine Garantie für ursprüngliches Feld oder Passwortfeld-Erkennung behaupten.
- Keyboard-only-Portal-Freigabe, keine Bildschirmaufnahme, Maussteuerung, Root-/uinput-Lösung oder versteckte Desktop-Sonderfreigabe.
- Erneuter Freigabedialog beim App-Start ist akzeptiert; nicht erst nach einem Diktat fragen.
- Bewusster Download der festgelegten Whisper-/Qwen-Testmodelle ist erlaubt, ca. 787 MB; SHA-256 aus dem Katalog prüfen. Keine weiteren Installationen ohne Zustimmung.
- Sichtbare Texte DE/EN; Cloud standardmäßig aus; keine Diktat-Historie; keine Schlüssel/Portal-Tokens in Exporten, Logs oder Git.
- AppImage-GLIBC-Obergrenze `2.35` erhalten. RPM und AppImage liefern, Sidecar einschließen, unsignierte Pakete ehrlich kennzeichnen.
- Nur eigener Branch `feat/v1-fedora-release`. `.github/workflows/platforms.yml` ist unversionierte Nutzerarbeit und bleibt unberührt.
- Erst nach Umsetzung Issues lesen. Nur vollständig erfüllte Anforderungen nachträglich mit Nachweisen schließen.
- Drei DeepSeek-Prüfberichte liegen vor; zwei weitere Helfer scheiterten am Gratislimit. Haupt-Agent implementiert/prüft selbst, keine bezahlten Ersatz-Helfer.
- Jeder Cargo-Aufruf mit `--manifest-path`; Builds/Tests/Clippy zusätzlich `--locked`. Zwei unabhängige Cargo-Projekte.

## Review Focus

1. Widerruf/Abbruch während asynchroner Ausgabe: kein später Tastendruck und keine Ausgabe aus einer alten Sitzung (Task 2).
2. Zwischenablage mit Bild, mehreren Formaten oder neuer Nutzerkopie: keine stille Datenvernichtung/ungeprüfte Wiederherstellung (Tasks 1–2).
3. Gehaltene Steuer-/Sondertasten sowie Absätze: keine Shortcuts oder unbeabsichtigten Enter-Aktionen statt Text (Tasks 1–2).
4. Defekte Settings, fehlendes Tray und verschobenes AppImage: App bleibt erreichbar; kein falscher Autostart-Erfolg (Task 3).
5. Import auf anderes Gerät und fehlende Freigabe/Keyring: keine übertragene Eingabeberechtigung, kein Klartext-Token und kein falscher Ready-Status (Tasks 2–4).

## Reihenfolge und Dateigrenzen

1. `src-tauri/examples/wayland_output_probe.rs`: isolierter technischer Nachweis, kein Mikrofon und keine privaten Texte.
2. `src-tauri/src/wayland_output.rs`: Portal-Sitzung, Zustände, Ausgabe, Abbruch; `app.rs` bleibt Koordinator.
3. `src-tauri/src/desktop_integration.rs`: Linux-Autostart/Startsichtbarkeit; Settings und Tray-/HUD-Integration separat von Spracherkennung.
4. `src/pages/`, kleine gemeinsame UI-Komponenten, `src/messages.ts`: vorhandene Funktionen in fünf Bereiche einordnen, kein Engine-Umbau.
5. Linux-Paketprüfer/Workflows: RPM, stabile Tags, Fedora-Abnahme, dauerhafte Nachweise.

Diese Teilbereiche werden getrennt committet/geprüft, aber als ein V1-Vorhaben integriert. Task 1 ist die technische Schranke für alle größeren Umbauten.

Niemals einen Systemdialog selbst bestätigen. Auf erlaubten Testdialog warten, danach ausschließlich in ein bewusst bereitgestelltes Testfeld schreiben.

Andere Plattformen erhalten einen konsistenten Unsupported-Stub, keinen Linux-Import.

- [ ] Worker implementieren: explizite Freigabe, Pending/Ready/Denied/Error, timeout/begrenzte Warteschlange, Session-Closed überwachen. Kein implizites Reconnect während Ausgabe. Transportentscheidung aus Task 1, keine zweite ungeprüfte Ausgabemethode.

Wenn Persistenz eingesetzt wird, Token nur über vorhandenen System-Keyring speichern/rotieren; bei fehlendem Keyring ohne Klartextablage und mit erneuter Freigabe arbeiten. Tauri-Befehl `request_insertion_permission` nur bei ausdrücklicher UI-Aktion/gespeicherter Einwilligung, `disable_insertion_permission` beendet die Sitzung.

## Verifikation und Arbeitsregel

Für jeden Task Rot-Grün-Nachweis vor Produktcode, anschließend fokussierte und angemessene Gesamtprüfungen. Je Task `docs/PROGRESS.md` auf den tatsächlichen Stand bringen. Keine pauschalen „fertig“-Aussagen aus Helferberichten. Wenn Gratis-Helfer weiter nicht verfügbar sind, transparent selbst prüfen statt unbestellte Modelle zu starten.

Der konkrete Wayland-Transport ist absichtlich an den praktischen Task-1-Nachweis gebunden. API-Anwesenheit allein und ein erfolgreicher Build heben diese Schranke nicht auf.
